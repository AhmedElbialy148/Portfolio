# Commit conventions

MIS uses [Conventional Commits 1.0.0](https://www.conventionalcommits.org/). The format is strict because release-note generation, changelog tooling, and triage filters depend on it.

## Format

```
<type>(<optional-scope>): <imperative summary, ≤ 72 chars>
<blank line>
<body — what & why, wrap at 72 chars>
<blank line>
<footer — ticket refs, BREAKING CHANGE>
```

The header (first line) is mandatory. Body and footer are optional but expected for anything non-trivial.

## Types

| Type       | Use for | Appears in changelog? |
|------------|---------|-----------------------|
| `feat`     | New user-visible behaviour | **Yes**, under "Features" |
| `fix`      | Bug fix | **Yes**, under "Fixes" |
| `perf`     | Performance improvement, no behaviour change | **Yes**, under "Performance" |
| `refactor` | Internal change, no behaviour change | No |
| `docs`     | Docs-only | No |
| `test`     | Tests-only | No |
| `build`    | Build system, package manager, deps | No |
| `ci`       | CI/CD pipeline | No |
| `chore`    | Everything else (housekeeping, tooling) | No |
| `revert`   | Reverts a previous commit (auto-generated by `git revert`) | **Yes** |

## Scope (optional)

A noun describing the area of the codebase: `auth`, `billing`, `api`, `web`, `infra`. Use the package or module name when one is obvious. Skip the scope rather than invent one.

Examples:

- `feat(billing): add Stripe webhook retry`
- `fix(auth): reject expired refresh tokens`
- `chore: bump node to 22.5`

## Subject (summary) rules

- **Imperative present tense**: `add`, `fix`, `remove` — not `added`, `fixes`, `removing`.
- **No trailing period.**
- **≤ 72 chars.** Aim for ≤ 50 if possible — GitHub truncates after that in many views.
- **No ticket id in the subject** — it goes in the footer. The PR title may include it in parentheses for readability.

## Body

Use the body to explain **what changed and why**, not how (the diff shows how). Wrap at 72 chars. Use bullet points freely.

Good body:

```
Stripe occasionally returns 5xx on the webhook endpoint, especially
during their incident windows. Previously we logged and dropped the
event, so subscription state could lag for hours.

This commit:
- adds an exponential backoff retry (4 attempts, 1s base)
- records each attempt to the audit log
- surfaces the final failure to Sentry with the event id
```

## Footer

Use the footer for:

- **Ticket references**: `Refs: MIS-142` or `Closes: MIS-142`.
- **Breaking changes**: `BREAKING CHANGE: <description of what breaks and the migration>`.
- **Co-authored-by** (humans only): `Co-authored-by: Name <email>`.

**Never** add an AI agent as `Co-authored-by`. The author of record is the human who reviewed and merged.

## Breaking changes

Two markers, both required:

1. A `!` after the type (and scope, if any) in the header:
   ```
   feat(api)!: drop /v1 endpoints
   ```
2. A `BREAKING CHANGE:` line in the footer describing what breaks and how to migrate:
   ```
   BREAKING CHANGE: /v1/* endpoints removed. Clients must move to /v2/*.
   See docs/migration-v1-to-v2.md for the field mapping.
   ```

## One commit per task

The branch may have many WIP commits while you work. Before pushing for review, squash them so the final history is **one commit per user story / task**. If a single PR truly contains two independent tasks, split it into two PRs.

Squash interactively:

```bash
git rebase -i origin/dev
```

…and use `fixup` / `squash` to collapse WIP commits into the lead commit for each task.

## Worked examples

### A small bug fix

```
fix(auth): reject expired refresh tokens

The refresh endpoint accepted tokens past their `exp` claim because
the JWT library was configured with `verify_exp=False`. Toggling it
back surfaces a 401 to the client, which our SDK already handles.

Closes: MIS-189
```

### A feature with a breaking change

```
feat(api)!: drop /v1 endpoints

The /v1 surface has been deprecated since 2025-09. Server-side metrics
show < 0.1% of traffic over the last 30 days, all internal.

BREAKING CHANGE: /v1/* endpoints removed. Clients must move to /v2/*.
See docs/migration-v1-to-v2.md for the field mapping.

Closes: MIS-301
```

### A dependency bump

```
chore(deps): bump axios to 1.7.4

Picks up the CVE-2024-39338 SSRF fix. No code changes required.

Refs: MIS-318
```

## Commit template

See `assets/commit-template.txt`. Install once per machine:

```bash
cp assets/commit-template.txt ~/.config/git/mis-commit-template.txt
git config --global commit.template ~/.config/git/mis-commit-template.txt
```

From then on, `git commit` (without `-m`) opens an editor pre-filled with the structure above.

## Tooling

- **commitlint** (recommended): drop `assets/.commitlintrc.yaml` into the repo if you want CI to reject malformed messages. (To be added when adopted by the team.)
- **`gh pr create --fill`** reads the latest commit message into the PR title and body — which is why the format matters even for one-commit PRs.
